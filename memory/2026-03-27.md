## Docker Container Reconfiguration Project

**15:00-19:20** — Resolução completa de acesso Docker na VPS

### Problema Inicial:
- OpenClaw rodando em container Docker sem acesso ao socket
- HTML files (`carteira-app.html` e outros) inacessíveis fora do container
- Portas não mapeadas para acesso externo

### Solução Implementada:
1. **Diagnóstico completo** do container atual (`e8534df8673c` → `95277a2737af`)
2. **Criação de novo container** com acesso total:
   ```bash
   docker run -d --name openclaw-permanent \
     -v /var/run/docker.sock:/var/run/docker.sock \
     -v /data/.openclaw:/data/.openclaw \
     -v /var/log/openclaw:/var/log/openclaw \
     -p 8000:8000 -p 8080:8080 -p 9000:9000 \
     --restart unless-stopped \
     ghcr.io/hostinger/hvps-openclaw:latest
   ```

### Desafios Encontrados:
1. **Porta 45154 em conflito** → Container atual já usando
2. **Container falhado bloqueando nome** → Removido com `docker rm`
3. **Porta 8000 já em uso dentro do container** (processo desconhecido)
4. **Arquivos HTML desaparecidos** no novo container (só config files)

- Port conflicts são comuns em reconfigurações
- Persistência de arquivos via volumes funciona, mas conteúdo pode divergir
- Manter container antigo durante transição evita downtime
